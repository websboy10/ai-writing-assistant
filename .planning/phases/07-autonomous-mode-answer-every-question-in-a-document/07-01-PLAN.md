Prove — or disprove — the two unproven mechanisms the whole Google Docs path
rests on, before a single line is built on top of them.

1. **Can the extension get a Google Docs API token at all?** `chrome.identity.getAuthToken`
   against a second "Chrome Extension" OAuth client (D-17). Whether this works for an
   unpublished/sideloaded extension is unverified (RESEARCH Assumption A2), and the

   to discover later.

   Docs renders to canvas, but the Find bar is real DOM. If Find can put the cursor at
   a question we read from the API, the existing `InsertionSession` + `GDocsAdapter`
   types the answer there letter by letter, locally, with zero write quota.

Purpose: D-16a makes this a hard gate. Plan 07-05 (the Google Docs path) does not start
until `07-SPIKE.md` carries a verdict.
Output: token plumbing that is needed under either verdict, a spike page that runs the
four probes against a real document, and a written GO/NO-GO.

Add the Docs API token path. Three one-shot message kinds, all handled in the
background service worker. **The access token never leaves the background worker** —
callers get results, never credentials.

`protocol.ts` — extend `OneShotRequest` with:
- `{ kind: 'docs-auth'; interactive: boolean }` → data `{ granted: boolean }`
- `{ kind: 'docs-get'; documentId: string }` → data `{ title: string; paragraphs: DocsParagraph[] }`
- `{ kind: 'docs-batch-update'; documentId: string; requests: unknown[] }` → data `{ replies: unknown[] }`

Export `interface DocsParagraph { index: number; text: string; startIndex: number; endIndex: number; namedStyleType?: string }`
and `export const DOCS_SCOPE = 'https://www.googleapis.com/auth/documents';`

`wxt.config.ts` — add an `oauth2` manifest key holding `client_id` from
`process.env.VITE_GOOGLE_DOCS_CLIENT_ID` and `scopes: [DOCS_SCOPE]`. Include the key
ONLY when that env var is set, using the same conditional-spread pattern already used
for `isLocalBackend` — an `oauth2` block with an empty client_id is worse than no block.
Request `documents` and nothing else: never `drive`, never `drive.file`.

`background.ts` — add to `handleOneShot`:
- `docs-auth`: call `chrome.identity.getAuthToken({ interactive: msg.interactive, enableGranularPermissions: true })`.
  Handle BOTH return shapes (recent Chrome resolves an object with `token` and
  `grantedScopes`; older Chrome resolves a bare string). No token → `{ ok:false, status:401 }`
  with a specific Danish message telling the user Google-adgang blev ikke givet og at
  panelet bruger reservevejen. If `grantedScopes` is present and does NOT include
  DOCS_SCOPE → call `chrome.identity.removeCachedAuthToken` for that token and return
  `{ ok:false, status:403 }` with a message naming the unticked Docs permission
  explicitly. If `grantedScopes` is absent (older Chrome), do not assume success —
  a subsequent 403 from `docs-get` is the authority.
- `docs-get`: fetch `https://docs.googleapis.com/v1/documents/{documentId}` with the
  Bearer token, walk `body.content`, and return one `DocsParagraph` per non-empty
  paragraph, carrying `startIndex`/`endIndex` straight from the API and the array
  position as `index`. Map 401 → clear the cached token and retry once; map 403/404 to
  a specific message that the signed-in Google account in this Chrome profile has no
  access to that document.
- `docs-batch-update`: POST `.../documents/{documentId}:batchUpdate` with
  `{ requests }`; return the parsed replies. Map 429 to a specific "Google begrænsede
  antallet af skrivninger" message.

Never log, never return, and never put in an error string: the token value.
Store nothing in `chrome.storage` — Chrome owns this token's cache and refresh.

Build the probe. Two pieces.

**`insertion/autonomous/docs-find.ts`** — production code, reused by plan 07-05.
Export `FIND_INPUT_SELECTOR` and `async function findAndPlaceCursor(questionText: string): Promise<{ ok: boolean; reason?: string }>`.
Sequence:
1. Dispatch a Ctrl/Cmd+F `keydown` (platform-detected the same way `GDocsAdapter.undoAll`
   detects it) at `gdocsEventTarget()`. Poll for `FIND_INPUT_SELECTOR` in the main
   document for up to 2000 ms.
2. Set the find input's value using the native `HTMLInputElement.prototype.value`
   setter followed by a bubbling `InputEvent('input')` — the same technique
   `PlainAdapter.setValue` uses, because Docs' find box is a framework-controlled input
   that ignores a plain assignment. Then dispatch `Enter` keydown/keyup on it.
3. Wait for Docs to move the selection, then dispatch `Escape` keydown to close the
   find bar so the document keeps focus.
4. Confirm positioning through the channel that already exists: `GDocsAdapter.hasSelection()`
   must become true. That is the hidden-mirror read channel at gdocs.ts:67 and it is the
   only observable proof available on a canvas-rendered page.
Every failure returns a specific `reason`. Never return ok:true on a timeout — a silent
no-op here would write an answer at the wrong place in the user's document.
Truncate the search string to Docs' find-field limit and use the first line of the
question only if it contains a newline.

**`entrypoints/spike/`** — a WXT extension page (NOT part of the sidebar UI, not
reachable from it, reachable only at `chrome-extension://<id>/spike.html`). One text
field for a Google Doc URL and one "Kør spike" button. It runs four probes in order and
prints a plain-text report with a copy button:
- **P1 token**: `docs-auth` with interactive true → granted / declined / partial grant.
- **P2 read**: `docs-get` on the doc id parsed from the URL → paragraph count, and the
  first three paragraphs with their startIndex/endIndex.
- **P3 find+type**: send `{ type: 'awa-docs-spike', questionText }` to the docs.google.com
  tab; the content-script handler calls `findAndPlaceCursor`, then `GDocsAdapter.prepare()`
  and one `insert()` of the marker string `⟪AWA-SPIKE⟫`. Then re-run `docs-get` and
  report the character distance between the question's `endIndex` and the marker's
  position in the re-read text.
- **P4 write**: one `docs-batch-update` inserting `⟪AWA-BATCH⟫` at a known index, then a
  second one deleting both markers again, to confirm the fallback path has write access.
Run P3 twice: once with an ASCII question and once with a question containing æ, ø and å
(the Docs API counts UTF-16 code units, and Danish text is this product's normal case).

Add the message handler in `entrypoints/content/index.tsx` via
`chrome.runtime.onMessage.addListener`, guarded so it only responds on docs.google.com
and only to the `awa-docs-spike` type.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Chrome profile → Google | OAuth consent; the user may grant less than requested |
| background service worker → docs.googleapis.com | The only place the access token exists |
| background worker → content script | Results cross here; credentials must not |
| docs.google.com page → extension | Document content is untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | Google access token | mitigate | Token lives only inside `handleOneShot`; never returned to callers, never written to `chrome.storage`, never interpolated into an error string or a log line. Chrome owns cache and refresh. |
| T-07-02 | Elevation of Privilege | `docs-auth` granular consent | mitigate | Check `grantedScopes` for `.../auth/documents`; a partial grant calls `removeCachedAuthToken` and returns 403 with a specific message. Where `grantedScopes` is unavailable, a 403 from `docs-get` is authoritative — success is never assumed. |
| T-07-03 | Elevation of Privilege | OAuth scope breadth | mitigate | Exactly `.../auth/documents` in the manifest. Never `drive`, `drive.file`, or any admin scope. Asserted by a grep gate in task 1. |
| T-07-04 | Spoofing | Chrome-profile Google account ≠ document owner's grants | accept | Reported as a specific 403/404 message telling the user which browser profile was used. Adding `identity.email` to read the profile address would widen store-review surface for a message-only improvement. |
| T-07-05 | Tampering | Spike writes markers into a real document | mitigate | Markers are fixed sentinel strings; P4 deletes both again in the same run; the operator uses a throwaway test document created for this purpose. |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install occurs in this plan. `chrome.identity` is built into Chrome and the Docs API is reached with `fetch`, matching the repo's existing no-SDK house style (RESEARCH.md Package Legitimacy Audit: intentionally empty). |
</threat_model>
