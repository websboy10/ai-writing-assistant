<objective>
The thinking half of autonomous mode: hand the backend a document (or a marked
selection) and get back, for every question in it, an answer grounded in that document
and the files already attached in the panel.

The AI decides what counts as a question (D-10). Real questionnaires use
"Beskriv dine tre vigtigste resultater", numbered fields, and headings with blank space
beneath them — a rule about question marks would miss most of a real form.

Purpose: this is the only piece that must run server-side. It reuses the existing
quota gate, entitlement gate and policy-gated model chain exactly as `/api/chat` does;
no new provider surface, no OpenRouter call from the extension.
Output: `POST /api/autonomous/answer`, a defensive parser that never trusts the model's
JSON, and the shared types the extension will build against.

**Deliberately not in this plan:** anything that knows about Google Docs, the DOM, or
insertion. This route receives an ordered list of paragraphs and returns answers keyed
to that list. That is what lets one engine serve both entry points and all three editors.
</objective>

`prompt.ts` (in `autonomous/`): export `detectionMessages(req)` and
`answerMessages(req, batch)`, both returning `ChatMessage[]` built from discrete
sections in the same style as `assembleMessages`.
- Detection: hand the model the paragraph list as numbered lines and ask which of them
  are things a person is expected to answer. State explicitly that a question mark is
  not required — numbered fields, imperative prompts ("Beskriv…"), and headings with
  blank space beneath them count. Ask for a JSON array of
  `{ paragraphIndex, questionText }` where `questionText` is quoted verbatim from that
  paragraph. Request `response_format: json_schema` support is NOT assumed — the prompt
  must ask for bare JSON and the parser must cope either way (RESEARCH A4).
- Answering: for each batch of `ANSWER_BATCH_SIZE` questions, send the questions, the
  surrounding document text, and the attached context items under a
  `# Attached context` section identical in shape to `assembleMessages`. Require a JSON
  array of `{ paragraphIndex, answer, grounded }`, where `grounded` is false when the
  answer could not be based on anything in the document or the attached material.
  Instruct the model to answer every question regardless — D-12 lists the gaps in the
  panel, it never withholds an answer.

`routes/autonomous.ts`: export `autonomousRoutes(app)` and register it in `index.ts`.
`POST /api/autonomous/answer`:
1. `verifyUser` → 401 with code `unauthenticated`, message in Danish, same shape as chat.ts.
2. `getEntitlement` with the `x-awa-install` header → 402 `payment_required`, same message as chat.ts.
3. Validate: `paragraphs` non-empty array; total text ≤ `MAX_AUTONOMOUS_DOC_CHARS` → else
   400 with a specific message naming the limit and suggesting a marked selection instead.
4. `consume_quota` with `p_cost: 2` (a run costs a detection call plus at least one
   answer call — charge honestly). On `!quota.ok` → 429 with the same shape chat.ts uses.
5. Detection call → `parseDetection`. Zero questions found → `refund_quota` p_cost 2 and
   return 200 with `{ answers: [], detected: 0 }` so the panel can say plainly that no
   questions were found. That is a result, not an error.
6. Answer calls in batches of `ANSWER_BATCH_SIZE` → `parseAnswers`, concatenated.
7. Respond `{ answers, detected }`.
Errors: `PolicyError` and `NoModelsError` map to the same specific messages chat.ts uses.
Any path that produced zero answers refunds the quota, mirroring chat.ts's WR-06 rule.

| Boundary | Description |
|----------|-------------|
| extension → backend | Untrusted request body: paragraph text, size, and scope |
| backend → OpenRouter | User document content leaves the machine here |
| model → backend | Model output is untrusted input, especially indices |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-06 | Information Disclosure | Whole documents sent to the model | mitigate | Route hardcodes `contentClass: 'real'`, so `streamChat` uses the paid chain with `provider.data_collection: 'deny'` (QUOT-05). | T-07-07 | Tampering | Model-returned `paragraphIndex` | mitigate | `parseDetection`/`parseAnswers` bounds-check every index against the paragraph list the backend received; out-of-range items are dropped. No model number ever becomes a document offset. |
| T-07-08 | Denial of Service | Oversized documents / question floods | mitigate | `MAX_AUTONOMOUS_DOC_CHARS` (60 000) rejected at 400 with a specific reason; `MAX_AUTONOMOUS_QUESTIONS` (40) caps the answer loop; the existing global `@fastify/rate-limit` 60/min applies. |
| T-07-09 | Spoofing | Unauthenticated or unentitled use | mitigate | `verifyUser` then `getEntitlement` then `consume_quota`, in that order, before any model call — identical to `/api/chat`. |
| T-07-10 | Repudiation | Quota charged for nothing | mitigate | `refund_quota` on every zero-answer path, mirroring chat.ts's WR-06 rule. |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install occurs. The test runner is Node's built-in `node:test` driven by `tsx`, already a backend devDependency in the lockfile — no new package enters the tree (RESEARCH.md Package Legitimacy Audit: intentionally empty). |
